# 工作区目录选择器

## 行为

- 搜索中的「打开工作区」、侧栏添加项目和草稿中的「打开文件夹」仍打开系统目录选择器，由用户选择项目文件夹；不是在文件管理器中打开当前目录。
- Renderer 只向 `addProject` 传当前任务 ID（无任务传 `null`）。Main 通过 `SessionHost.workspaceInfo` 读取该任务实际 `cwd`，包括 worktree 和无项目任务的工作目录。
- 若当前任务的 `cwd` 是仍存在的绝对目录，选择器以该目录作为 `defaultPath`；无任务、会话失效、目录删除或路径不是目录时，回退用户主目录。目录检查异步执行，不创建目录，也不使用进程启动目录。
- 取消或没有选中文件夹时不保存项目、不创建或切换任务。成功选择后的项目保存和各入口现有任务创建/选择语义保持不变。
- 不增加最近目录偏好、新配置或其他工作区管理功能。

## 参考与边界

- 对照的 ZCode 与修复前 ZPI 都未给目录选择器传 `defaultPath`；不能从源码证明系统为何显示 Downloads，也没有 Downloads 硬编码。
- 上述默认目录规则是明确的 ZPI 体验改进，不是 ZCode 已实现的行为。

## 验收

- Node 回归覆盖当前任务实际目录、worktree 与项目根目录不同时的实际目录、无项目任务默认目录、无任务/失效会话、缺失/已删除/普通文件/相对路径的回退。
- 取消和空结果不保存项目，成功选择只保存用户所选目录；目录选择失败继续按现有错误链报告。
- Preload 回归验证 `addProject` 把任务 ID 或 `null` 作为唯一参数传给 Main；所有 Renderer 入口使用同一接口。
- 执行定向单测、check 和 build；未运行原生 GUI 时明确记录，不能将 mock 验证说成原生面板复现。
