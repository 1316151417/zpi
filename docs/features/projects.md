# 项目、任务和 Git 工作树

项目把一个本地目录加入侧栏。任务绑定项目及执行目录；分组只是组织任务的方式，不改变文件位置。

## 添加项目和无项目任务

侧栏添加、搜索中的“打开工作区”、新草稿的“打开文件夹”都打开系统目录选择器。默认优先当前任务所属项目根目录，包括工作树任务；无项目时使用任务实际 cwd，不可用时回退用户主目录。取消不创建或切换任务。

无项目草稿分配 `~/.zpi/workspace/draft-<任务 UUID>`。同一草稿、其辅助对话和子智能体复用该路径；重启保留它。读取旧任务不创建新目录，删除任务也不递归删除这个目录。

## 三种浏览方式

| 视图 | 顺序和范围 |
| --- | --- |
| 按项目 | 项目内运行任务优先，再按更新时间；项目自身可拖动排序 |
| 按分组 | 组、组内任务和未分组任务保留手工顺序 |
| 最近更新 | 所有未归档主任务按更新时间排列，包含隐藏项目的任务 |

新项目插入顶部，重新添加同一真实目录复用项目身份和排序槽。“从侧栏移除”只隐藏项目，任务仍保留项目归属和 cwd；重新添加目录才重新显示项目。

置顶任务在相应视图中提供快捷入口；归档从活动列表隐藏，恢复保留组织关系。任务搜索帮助定位隐藏项目中的任务。

## 分组

在分组视图创建分组，支持名称、七种颜色、折叠和拖动。一个任务最多属于一组，重名组可以存在。删除组只解散归类，不删除任务。

组内新建把草稿放在该组；同目标已有草稿时可复用。置顶、归档不会丢失分组成员关系。拖动时如果来源组或落点已被其他操作改变，程序拒绝过期操作并刷新当前状态。

## 创建工作树

1. 在新任务草稿打开本地环境菜单，默认 Command/Ctrl+J。
2. 启用新工作树，选择起始本地或远程分支。
3. 首次发送时创建独立检出目录，然后在该目录执行任务。

默认基于当前提交，创建的是 detached HEAD，不自动新增本地分支。远程引用来自本地已有记录，程序不在选择菜单时自动 fetch。要保留为分支，可在工作树中显式执行 `git switch -c <分支名>`。

未提交改动不会被复制到新工作树。没有提交的 Git 项目不能建立这条工作树路径。工作树只隔离检出目录；各任务仍以当前系统用户的权限执行。

## 注意目录归属

辅助对话和子智能体共享父任务 cwd。已经打开的文件标签记住自己的目录；任务后来切换目录时，旧标签不会自动改为新目录，新标签采用新的工作目录。
