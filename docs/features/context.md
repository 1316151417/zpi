# 上下文、项目指令和技能

模型看到的上下文包括系统指令、当前有效历史、用户输入、引用材料和工具结果。主动提供相关材料能让任务范围更明确。

## 文件、会话和选区引用

- `@` 搜索并引用工作区文件；文件树拖入输入框使用同类引用。
- `#` 选择已有会话引用，由主进程按当前上下文读取和整理。
- 选中文字可以加入当前输入；预览中的行备注携带文件、行号、所选代码和备注。
- 图片可以作为附件加入，纯图片消息也需使用支持图片的模型。

引用不是把整个工作区自动上传。实际输入准备会解析引用并应用数量、长度和文件边界。文件备注只加入草稿，发送时才进入模型上下文，不直接改写源文件。

## 项目指令

`/init` 用于生成项目指令。程序支持用户级与项目根目录的 AGENTS 文件，具体加载顺序见[资源原理](../internals/resources.md)。任意嵌套目录的 AGENTS 不会因为工具进入该目录自动进入加载列表。

设置中的追加指令和交互方式影响新对话保存的配置。指令是给模型的文字约束，不是文件或进程权限隔离。

## 技能

技能位于用户或项目的 `.agents/skills`、`.zpi/skills`，每个技能目录包含带 frontmatter 的 `SKILL.md`。输入 `$` 或在斜杠菜单选择技能；选择不会自动发送。

程序先加载名称、描述和路径目录，明确使用时再读取正文。同名技能有确定覆盖顺序，禁用高优先级技能不会自动启用被覆盖的旧版本。设置中可以查看发现结果和诊断。

最小示例：

```markdown
---
description: 检查项目的公开接口和错误处理
---
先阅读接口，再验证正常、失败和取消路径。
```

技能名称来自父目录名称。正文相对路径相对于技能目录解释。

## 压缩对话

`/compact` 请求手动压缩；自动压缩在上下文接近预算时触发。程序总结较早内容并保留近期上下文，工具调用与结果须成对处理。压缩失败或取消会保留原历史。

长历史可以继续查看，发送给模型的内容则以最新有效摘要和保留消息为主。压缩不能保证保留每个细节；重要需求应写在项目指令或当前任务要求中。

## 图片和超限

单图导入和整个请求分别有预算；工具读取图片与用户附件的处理预算也不同。图片可能被缩放和有损压缩，旧媒体可能只在请求副本中被省略。当前附件超出总预算时会拒绝发送，不能通过丢掉当前图片假装成功。

预算内原图可能保留 EXIF/GPS、注释等元数据并发送给提供商；需要去除时应先在本地处理。图片体积、上下文 token 和服务端 HTTP body 上限是不同限制。

原理：[上下文与媒体预算](../internals/context.md) · [资源加载](../internals/resources.md) · [输入准备](../internals/input.md)。
