# 短期与长期记忆

“设置 → 记忆”提供两种互斥模式，默认都关闭。开启一种会关闭另一种，切换保留数据。新对话首次发送保存模式，已有对话保留自己的配置。快速对话不读取或生成记忆。

## 短期记忆

短期记忆适合少量稳定偏好和项目约束，保存在用户 `~/.zpi/MEMORY.md` 和项目工作区 `.zpi/MEMORY.md`。无项目任务只加载用户文件；工作树使用自己目录里的项目文件。

示例：

```markdown
# Memory
- [language] 默认中文交流，代码标识符使用英文。
- [verification] 改完文件后说明实际运行的检查。
```

每项使用 `- [id] 正文`，ID 唯一。设置中的“查看”不创建文件；“编辑”在缺失时创建初始文件。可明确要求主 Agent 记住、纠正或忘记某项内容，它使用普通文件工具维护。

格式错误、重复标识、编码错误和超限会使整份文件不被自动注入，并展示诊断；另一范围的合法文件仍可使用。程序不静默截断原文件。容量和解析规则见[记忆原理](../internals/memory.md)。

## 长期记忆

长期模式从符合条件的历史会话中提取来源摘要，再由后台 Agent 增量维护总摘要。新用户轮次自动读取简短总摘要；详细会话摘要与原始证据按需读取。

默认模型跟随触发会话，也可手动指定及分别覆盖提取、整合阶段。可以暂停自动生成、立即检查更新、查看状态与来源、清空长期库。

触发检查不等于必定调用模型：没有符合年龄/空闲条件的来源，或输入未变化时可以跳过。它没有按固定时钟独立唤醒的 cron。后台模型调用可能产生额外用量，单独统计。

## 明确记住和忘记

长期模式中，用户明确的记住、纠正或忘记要求写成独立 ad-hoc note，再由后台整合处理。主 Agent 不直接改生成摘要。notes 正文不会自动全部注入新会话，整合成功后才通过总摘要影响后续上下文。

暂停期间仍可保存请求文件，恢复并触发检查后再整合。失败或取消保留上一份有效摘要和未完成请求。

## 停用与清空

全局关闭长期生成或暂停会取消后台批次；已有会话仍可按自身配置读取已保存记忆。清空先停止写者，删除长期库并记录历史清空边界，保留原始会话和短期文件。

删除或编辑来源历史会撤销相应来源，下一次整合传播变化。自然语言结论的正确性仍依赖模型判断，当前用户要求和项目指令高于记忆。
