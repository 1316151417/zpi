# 三份快速对话审查结论复核

基线 `a0a6995`（0.2.118），修复 0.2.120（保留后续 main 的 abf79a4 / 0.2.119）。三份输入依次为 GLM、DeepSeek、MiMo；按实际源码和可复现行为判定，不以报告严重度作为证据。

## 逐项结论

| 报告项 | 判定及处理 |
| --- | --- |
| GLM 1：重呈现窗口跳位 | 确认。已聚焦可见的大窗带入内容会丢掉拖动位置，指针在另一显示器时会换屏。保留这种重呈现的位置；隐藏或未聚焦的唤起仍按原策略选屏。双显示器几何替身旧版失败、修复通过，未做双显示器实机验收。 |
| GLM 2：复制时物理 Option/Shift 尚未松开 | 尚未证明。没有给出实际受影响应用或实体输入证据。保留现有事件 flags、复制结果与剪贴板变更校验，不据此新增 250ms 等待。 |
| DeepSeek 1、2：原生调用重入 hide 后继续 show、写回旧来源 | 确认状态机缺口。restore/setMinimumSize/setBounds 内取消后不得继续 show；activate 内取消后不得保存旧 owner。每个原生步骤后校验原有 epoch/window/intent，旧清理也不能隐藏新唤起。可控事件顺序旧版失败；不声称采到了原生 Space 通知的同样重入顺序。 |
| DeepSeek 3：pending reset 的普通恢复模式不一致 | 确认。reset 尚未结束时提前计算的 composer 判断基于旧历史，随后空白大窗未折叠。改为 reset 完成后判断；测试对比 reset 在恢复前/后结束，两者收到真实形式的空白回包后均紧凑。超时 unknown 保留草稿属于既有保护，不能把 unknown 与确认空白的差异本身算 bug。原来依赖超时断言大窗的测试已纠正。 |
| DeepSeek 4：旧默认绑定没有在线迁移 | 不按 bug 修改。SQLite 读取明确不在线改写已保存绑定，测试明确覆盖主动设回 Alt+N/Alt+Shift+N、清空及停用后的保留。默认值变化不能区分旧默认与主动保存的相同组合。提升离线 migration 版本还会使当前 SQLite 版本校验拒绝旧记录。文档说明新默认与已有配置的区别，不覆盖用户设置。 |
| DeepSeek 5、MiMo 1：截图隐藏丢失来源焦点 | 确认，且有本机原生前后证据。新增 capture-hide 语义，在截图前归还焦点；取消保留来源，成功重新呈现时重新捕获来源。主窗显隐及窗口顺序保持原状。 |
| DeepSeek 6：send IPC pending 时 Esc 丢失或隐藏 | 确认。通用 boolean lock 换为有归属的操作记录，stop 可排在 send 后；send 的 finally 不清理 stop，重复 Esc 合并。旧会话的排队 stop 不得停止新会话。快照到达前/后两种 deferred IPC 用例均先失败再修复。 |
| DeepSeek 7：空剪贴板 V 仍显示错误 | 确认与静默读取语义不一致。空文字或空白且无图片时返回无内容，不打开浮窗或改草稿；超限内容等可操作错误保留。 |
| DeepSeek 8、MiMo 2：原生模块及焦点异常边界 | 确认条件性故障。模块改为首次唤起时加载，校验导出及 owner；失败仅记录一次并降级为 Electron 应用激活，主应用可以启动。焦点归还失败记录后仍完成面板清理；toggle 的同步异常转为 Promise 拒绝；截图 hide 进入既有 capture 的 Promise 错误边界。补齐 Node-API 返回值、finalizer 失败释放和空异常原因。正常打包路径未发现错误，不将故障注入说成已观察到原生崩溃。 |

其他备注：按最后一次发送计时的 15 分钟过期取消是现有明确语义；一次只处理一个捕获、跨类型按键合并也沿用原策略；未改为多捕获队列。无生产调用方的 newConversation 测试入口没有作为行为 bug 删除。

## 原生截图前后对照

测试启动两个隔离 Electron 实例，仅以本地 PNG 注入截图来源；使用真实控制器、AppKit 激活、窗口、preload/IPC 和 React 附件导入。没有真实系统截图、系统剪贴板、付费模型或用户编辑器输入。

对照仅将窗口控制器临时替换为 `git show a0a6995` 的源码，由 try/finally 恢复工作区修改。这样隔离出旧 hide 的因果，不回滚任何真实数据。

- [旧版记录](capture-before.json)：截图前隐藏后，ZPI 主窗 visible=true、focused=true，WindowServer 顺序位于来源应用之前；来源应用在 5 秒内未取回焦点，测试失败。
- [修复记录](capture-after.json)：截图取消与成功两轮，在捕获期间及最终收起后均为来源应用前台，主窗 visible=true、focused=false、appHidden=false，WindowServer 顺序始终在来源之后。成功时真实 renderer 保留原草稿并导入 PNG。

用户看到的白色 Electron 窗口来自此测试的占位主窗。收到打扰反馈后不再启动可见测试；测试进程及隔离窗口已退出。占位窗现增加明确标题和说明，未来可见测试需重新确认时间。

## 验证与边界

- 窗口/renderer/capture/原生加载器的聚焦单元测试：351 通过，之后补充了新会话排队停止与 minimum-size 重入用例。
- 最终全量单元：266 文件，3384 通过、1 跳过。后台 Electron：10 通过，包含第二作用域重建夹具。TypeScript/Biome/build 通过；已有 4 warning / 6 info 保留。
- 原生交互：7 通过，包括新截图取消/成功、原有焦点和 Esc、主窗新任务路径；完整生命周期项在构建阶段因 esbuild 服务已被上一作用域清理而失败，没有执行成功，不计入通过。
- 构建服务问题另以两个后台测试作用域复现：旧 helper 第二次构建报 “The service is no longer running”；构建后显式释放 esbuild 服务，避免复用已被 guardian 终止的子进程。该问题属于测试基础设施，不算产品故障。
- 收到用户反馈后不再重跑原生可见生命周期，不重启实际客户端。真实 A 截图手势、实体全局键、物理修饰键、跨 Space 精确重入时序、多显示器、不同 macOS 版本及打包失效场景尚未实机验收。
- 原生模块不可用时的 fallback 只保证应用继续可用，不能保证与正常原生焦点模块相同的窗口顺序；错误留在本地 error.log。
