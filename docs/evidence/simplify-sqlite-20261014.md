# feat-sqlite 简化复核（2026-10-14）

## 范围

以 `origin/main...HEAD` 收集已合入 main 0.2.53 的 SQLite 功能差异，范围为 82 个文件。功能基线为远程 `af7f278fd0ac120ac4cd4822081a1d4587fb150d`（0.2.54，树 `051daea158391d2a5d121ed2356ef943bfea3fd5`）。开始时没有未提交改动。四路独立复核分别关注复用、简化、效率和实现层次，全部报告完成后才统一应用。此次交付版本为 0.2.55，仍只推送 feat-sqlite。

## 应用的清理

- 复用已有目录同步、路径包含判断和记录大小常量，移除各自重复实现。
- 删除 v2 验证器明确拒绝后不可能执行的 model_change / thinking_level_change 分支；保留 run/context_anchor 的历史配置恢复。
- 迁移时运行状态只计算一次，避免 JSON payload 与 SQL 状态各维护一份表达式。
- 删除已由 defaultCapabilities 提供的不可达默认值补写；展平 SDK 思考强度选择，保持来源优先级。
- 队列保存只查询一次已接受输入；启动恢复只读取一次操作意图，并按任务和输入 ID 匹配。
- 任务列表通过一条查询复用同一个行解码器，不再逐任务重复查询。
- 历史正向/反向遍历直接解码本批已查询的偏移行，避免逐条再查询同一份元数据；仍读取并校验实际正文的 seq 与 ID。
- 历史索引重建、fork 暂存读取使用分片缓冲，一条跨 chunk 记录只合并一次；同步 readSync 复用缓冲区的分片拥有独立字节。
- chunk 未产生完整记录时，不再重复写入相同索引 watermark；保留完成记录的事务、同步保障、最终 flush 和合法缺换行尾部修复。

## 跳过的建议

1. 编辑恢复改为 SessionInputQueue 的新插入方法：涉及原差异之外的队列生命周期，以及更新锁、附件回滚和实时发布时序。本轮不改，避免把质量清理变成行为调整。
2. append 仅查询前一条记录 ID：现有 getLastEntry 同时重新解码和验证前一条正文。只取元数据会减少原有完整性检查，本轮保留。
3. 未合并旧格式解析器和运行时校验器，也未合并异步迁移持久化与同步运行时持久化；这些实现的边界和保证不同。

未引入新功能、改变存储格式、并行 SQLite 写入或删除持久化屏障。
