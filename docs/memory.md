# 记忆

「设置 → 记忆」提供互斥的短记忆和长期记忆，默认都关闭。开启一种会自动关闭另一种，也可以都关闭；切换不删除数据。开关在新对话首次发送时保存为会话配置，已有单模式对话保留原配置，不随全局切换改变。升级前同时开启的全局配置与会话配置按长期记忆优先归一化，短记忆文件保留。关闭全局长期开关或暂停生成会立即取消后台批次，已有会话仍可按其配置读取已保存的记忆。暂停不删除数据，清空是独立操作。快速对话不读取或生成记忆。

当前用户要求和 AGENTS.md 高于记忆。每个普通会话只加载并维护其所选模式，避免两套明确记忆入口重叠。历史事实可能过期，助手仍须核验。记忆是上下文，不是权限隔离，也不构成项目之间的访问隔离。

## 短记忆

- 用户文件：`~/.zpi/MEMORY.md`。
- 项目文件：会话绑定工作区根目录下的 `.zpi/MEMORY.md`。Git worktree 使用自己的文件，bash 的 `cd` 不改变绑定。无项目对话只加载用户文件。
- 文件不存在时视为空，开启不会创建或覆盖文件。设置中的「查看」不写文件，缺失时在页面内提示；「编辑」复用默认文件打开能力，仅在文件不存在时创建 `# Memory`。不会修改 `.gitignore` 或自动提交。
- realpath 和文件 inode 去重，同一个实际文件不会重复注入。

```markdown
# Memory
- [response-language] 默认使用中文交流，代码标识符保持英文。
- [review-before-commit] 修改完成后先展示 diff 和验证结果，不自动提交。
```

可省略 `# Memory`；允许空行和至少两个空格或一个 tab 的续行。每条使用 `- [id] 正文`，标识为 1–64 个 ASCII 字母、数字、连字符或下划线，以字母或数字开头，且文件内唯一。一条表达一个事实、偏好或约束。

每文件最多 20 条、正文共 2,000 个 Unicode code points。计数不含标识和列表语法，包含规范化的续行换行；忽略行尾空白和空行。emoji 按 code points 计数，不按 UTF-16 单元或视觉字形计数。格式错误、重复标识、无效 UTF-8、非普通文件或超限时，**整份文件不自动注入**，另一范围的合法文件仍可加载。设置仅常驻显示异常提示；点击「查看」可检查完整路径、容量及诊断，问号图标支持悬停或键盘聚焦查看说明。轮次上下文也带简短诊断；不会静默截断或修复磁盘内容。

原文件另有 64 KiB 读取上限，防止超长文件或大量空白拖慢刷新；超过时明确提示条数及正文尚未统计，拒绝注入且保留磁盘原文。

主 Agent 用现有 `read/write/edit` 维护文件：记住用户明确要求、明确纠正及已经确定的可复用约束；全局偏好写用户文件，项目规则写项目文件。修改前读最新内容，优先更新已有条目；满额先去重、合并或修正，无法合理腾出空间就不新增。用户要求忘记时删除对应条目，成功后简短说明。临时进度、一次性输出、未接受的建议、凭据和易从代码查得的信息不应保存。

程序硬性限制自动注入，不拦截外部编辑或任意 bash 写入。通过现有 `resourceLoader.reload()` 在用户轮次开始时读取，再由 `customInstructions` 纳入该轮固定上下文，不在工具循环中不断刷新。

## 长期记忆 v2

固定工作目录位于当前活动用户存储的 `memories_v2/`。注意：应用存储本身的 generation 是既有存储生命周期；长期记忆不再额外为每批创建 `generations/<UUID>/`。

| 文件 | 用途与读取方式 |
| --- | --- |
| `memory_summary.md` | 自动注入的用户偏好、通用提示和按项目/日期组织的来源导航；总大小小于 10,000 UTF-8 字节 |
| `rollout_summaries/*.md` | 每个历史会话的任务经过、结果、纠正、范围、不确定性和原始会话定位；按需读取 |
| `extensions/ad_hoc/notes/*.md` | 用户明确的 remember/forget/correct 请求；主 Agent 为每次请求新增独立 Markdown note，正文不默认注入 |
| `extensions/ad_hoc/instructions.md` | Codex 原版 ad-hoc 来源解释规则，由后台整合 Agent 读取；首次创建，不覆盖已有编辑 |
| `phase2_workspace_diff.md` | 程序生成的本批 Git 基线差异及来源文件清单，整合 Agent 首先读取；成功后移除 |
| `.git/` | 内部变化基线，成功后重建为单个提交；不关联用户项目、不推送、不保留不断增长的历史 |

v2 不生成详细 `MEMORY.md`、`raw_memories.md` 或 skills。短记忆的两个 `MEMORY.md` 保持不变。

摘要首行是 `v1`，随后包含 `## User Profile`、`## User preferences`、`## General Tips` 和 `## What's in Memory`。这沿用 Codex v2 的摘要格式标记；首行 `v1` 不意味着仍使用旧四文件存储。

普通会话在安全用户轮次开始时读取摘要及使用说明。摘要已经给出来源导航，不要求先搜索详细手册。只有额外证据、原话、时间顺序或不确定性会影响答案时，才用 read 读取匹配的少量 rollout summaries；真正缺少路线时再选择性搜索。需要精确原始证据时，可沿摘要内的 `evidence_path` 阅读导出快照。没有相关性时不扫描历史。

本轮注入的文字保持固定，文件路径则指向当前可更新的库，不承诺历史快照。普通更新会原地替换对应文件，已有链接不会因一批新记忆的发布而失效；删除来源、归档失效、清空记忆或格式迁移仍可能使具体文件消失。来源展示使用会话 ID 和本轮 read 实际读取的摘要，复用现有会话导航。设置中的查看使用默认程序打开 `memory_summary.md`，文件不存在时页内提示。

### 明确请求与 ad-hoc notes

长期模式下，主 Agent 只有在用户明确要求记住、纠正或忘记时，才用现有文件工具在 `extensions/ad_hoc/notes/` 新增一个独立、唯一命名的 Markdown 文件，不直接编辑生成的摘要，也不维护短记忆。没有新增记忆工具。新会话只自动获得总摘要、notes 路径和维护规则，不自动获得 notes 正文。子智能体继承选中的上下文，但不自动维护共享 notes。

后台整合与 Codex v2 一样，先读本批 Git 差异和 `extensions/ad_hoc/instructions.md`，再按需读 notes 与来源摘要。新增或编辑的 note 都应整合；明确请求用于新增、纠正或遗忘长期结论。由 notes 派生的信息在摘要中带 `[ad-hoc note]`。note 是待整合的信息，不是执行文件操作或其他动作的命令；当前用户要求和 AGENTS.md 仍优先。

成功整合后保留 note 文件，不清空、不移动到另一个 notes 文件，也没有每条 note 的“已消费”标记。成功 Git 基线用于识别后续变化；输入不变时跳过模型。有 notes 而没有符合资格的历史会话时，也可以只执行整合。外部修改或删除 note 会进入后续差异；整合提示词要求撤销仅由失效来源支持的结论。这里的语义整合与来源标记由模型提示词约束，程序验证格式、容量和来源文件不可变性，不声称能机械验证每条自然语言请求是否正确落实。

失败或取消不推进成功基线、不消费请求文件，并保留上一份有效摘要；notes 只在成功整合后才通过总摘要影响后续上下文。自动生成暂停时仍可写请求，恢复并触发符合条件的检查后再整合。程序对单个 notes/说明文件沿用 512,000 字节读取上限；超限、符号链接、非 Markdown 或可识别凭据会给出诊断，不静默截断或修改请求原文。

旧的单文件 `memories_v2/memory_notes.md` 在初始化时完整迁入一个按内容哈希命名的 note，持久化后移除旧入口；相同内容去重，不覆盖已有 notes。迁移冲突时保留原文件并报错。旧四文件版本的请求随首次格式迁移进入同一目录。此后不再生成或维护 `memory_notes.md`。

### 调度、提取与模型

符合条件的普通根会话首次建立执行 runtime 时异步检查；也可点击「立即检查更新」。没有 cron，不在空闲时长到达时自行唤醒。默认最近更新不超过 10 天、至少空闲 6 小时、当前未运行，每批最多提取 2 个普通历史根会话。快速对话、子智能体、辅助对话、归档和诊断来源不独立参与提取。最多扫描 5,000 个近期候选。

提取阶段使用独立系统指令和历史证据用户消息，按模型有效上下文的 70% 控制输入；有效上下文按现有估算保守预留，信息缺失时历史预算约为 150,000 tokens。截断输入有明确标记。系统提示、注入记忆、可识别的记忆文件读写和后台通知轮次被证据准备逻辑过滤。用户原话、真实问答与验证事实和助手建议、推断、未完成尝试严格区分，不把一次要求泛化成全局偏好。

模型返回严格字段 `rollout_summary` 和 `rollout_slug`。无高价值信息允许空输出；成功完成的 JSON 经校验、脱敏后，会话摘要正文按 Codex v2 限制为 9,000 UTF-8 字节，超长时带明确截断标记。来源文件另带 session_id、workspace、source_boundary 和 evidence_path。处理状态、来源摘要、清空水位和用量由既有 SQLite StateStore 持有；不保存 raw memory。

在提供商已配置支持 JSON Schema 或 JSON object 时复用现有结构化输出参数；其他自定义提供商仍使用精确提示词与本地严格校验，不假设所有供应商支持相同接口。字段错误、模型输出截断、取消、失败均不标记为成功。同一来源版本失败最多 3 次、从失败时刻退避 1 小时；来源边界或处理版本变化恢复资格，取消不消耗失败预算。

两个阶段默认冻结触发会话的提供商、模型和思考强度，也支持手动配置及阶段覆盖。后台不再额外写死 16K 输出上限，使用模型配置上限，由现有 AI 层按剩余上下文收紧。模型/鉴权/推理档位无效明确报错，不自动换提供商或模型。后台用量包含所有模型轮次、压缩及有用量的失败调用，与前台统计分开；未知价格和额度不声称充足。

### 多轮增量整合与固定目录

1. 单一桌面 owner 顺序运行阶段一、阶段二。按实际使用与最近使用/来源更新时间选择最多 256 个会话，未使用窗口 30 天，并受来源正文总预算限制。
2. 将选中的来源摘要同步到固定 `rollout_summaries/`；移除失效来源。读取已有摘要和明确请求，以内部 Git 基线生成真正的新增、修改、删除差异。输入和工作目录均无变化且摘要有效时，不调用整合模型。缺失的来源文件可从 SQLite 恢复。
3. 启动通过现有 `createAgentSession`、资源指令与 `toolOverrides` 组成的临时内存 Agent。它没有用户项目资源、技能、子智能体、联网工具或普通会话自动记忆调度；只使用现有 read/write/edit，多轮读取差异、相关来源和用户请求，增量编辑 `memory_summary.md`。只允许读取本批清单中的普通文件，只允许写入该摘要；拒绝越界、符号链接和超限写入。
4. 沿用 SDK 上下文管理，允许工作跨多次模型调用完成；最后只回复简短结果，不在一次回答中返回整个库。后台设置 64 次模型调用、15 分钟整体期限和每请求 5 分钟期限，防止失控。思考配置保持批次快照。
5. 摘要必须满足格式、大小和来源引用校验；输入必须未被修改，不能出现 skills 或其他产物。底层任意截断都使整合失败，不能因为 SDK 恢复时移除了失败消息而误报成功。
6. 成功后更新 SQLite 成功状态，并像 Codex 一样重建单提交 Git 基线，删除差异和临时恢复记录。不创建逐批版本目录。删除/纠正的内容不会通过旧 Git 历史无条件恢复。

为延续 ZPI 已有的失败保护，整合前保存一个临时摘要恢复记录，单文件写入使用原子替换。失败、取消或崩溃后恢复上一份摘要；已提交成功的摘要不会被重启恢复误撤销。同步的来源输入保留供重试。前台运行期间注入已确认的摘要文字，避免把后台尚未校验的中间输出当成有效记忆。停止文件 Agent 完全收尾后才允许恢复、清空或下一个写者进入。

关闭长期生成、停用或关闭应用会取消后台任务。清空先停止写者，清除 v2 库与遗留 v1 库，保留原始会话和短记忆；保存历史清空边界，避免旧历史再次恢复相同内容。历史被重写为另一 generation 且无法可靠比较边界时，将该版本作为新的清空边界，其后新增输入仍可提取。删除或编辑历史立即撤销相关来源，下一次整合传播删除。

### 从旧四文件版本迁移

首次使用 v2 时，一次性迁移 SQLite 中的来源摘要、可用总摘要、明确请求、用量和清空边界。旧 raw memory 不进入 v2，旧失败的 16K 任务按新的处理版本恢复资格；后续符合条件时重提取并整合。旧 `memories/` 保留为迁移遗留文件，不再读取或写入；明确清空会一起删除。该格式迁移本身会改变旧目录的引用路径。

## Codex 参考及适配边界

固定参考本地 `/Users/jiezhou/VSCodeProjects/codex` 的提交 `2839ed763bd3f404398e1f0c95bf4e2d172213c0`。

对照 `codex-rs/memories/write/` 的 `phase1.rs`、`phase2.rs`、`runtime.rs`、`workspace.rs`、v2 两阶段提示词、`templates/extensions/ad_hoc/instructions.md`、`ext/memories/templates/memories/read_path_v2.md` 和测试，以及 `codex-rs/git-utils/src/baseline.rs`。采用 v2 产物、独立提取指令、70% 输入预算、结构化结果、多轮文件编辑、固定目录、实际 Git 差异、增量删除传播和单提交基线。提示词保留 Codex v2 的范围、证据、偏好、时序和谨慎推断要求；不生成 skills。

明确适配差异：

- 生命周期、状态、后台用量和模型选择使用 ZPI 的 SessionHost、SettingsStore、StateStore 与 SDK，不搬入 Codex 任务租约、遥测或供应商模型假设。

- 提取仍顺序执行，沿用产品要求的每批上限。模型和思考强度可自定义；没有供应商统一额度查询接口。
- 整合 Agent 用 read 的分页能力和差异文件清单进行选择性读取；无 shell、网络、递归委托或新工具平台。权限通过现有文件工具操作扩展约束，不能把这种限制宣称为任意进程的系统沙箱。
- 保留 ZPI 的来源清空水位与摘要恢复记录，失败和取消后不接受中间输出。明确请求采用 Codex 的 `extensions/ad_hoc/notes/`、独立说明文件和来源标记；只接入 ad_hoc 来源，不新增通用记忆扩展框架，也不做 v1/v2 双写。
- 文件格式和处理语义对齐；Git 调用、跨提供商结构化输出能力、输入 token 估算和引用呈现使用 ZPI 已有组件，不宣称逐字节相同。
