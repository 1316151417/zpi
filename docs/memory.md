# 记忆

「设置 → 记忆」分别控制短记忆和长期记忆，默认都关闭。两个开关在新对话首次发送时保存为会话配置；旧对话保留原配置。关闭全局长期开关或暂停生成会立即取消后台批次，已有会话仍可按其配置读取已保存的记忆。暂停不删除数据，清空是独立操作。快速对话不读取或生成记忆。

当前用户要求和 AGENTS.md 高于记忆；明确的短记忆偏好高于长期记忆中的推断。历史事实可能过期，助手仍须核验。记忆是上下文，不是权限隔离，也不构成项目之间的访问隔离。

## 短记忆

- 用户文件：`~/.zpi/MEMORY.md`。
- 项目文件：会话绑定工作区根目录的 `MEMORY.md`。Git worktree 使用自己的文件，bash 的 `cd` 不改变绑定。无项目对话只加载用户文件。
- 文件不存在时视为空，开启不会创建或覆盖文件。设置中的「查看」不写文件，缺失时在页面内提示；「编辑」复用默认文件打开能力，仅在文件不存在时创建 `# Memory`。不会修改 `.gitignore` 或自动提交。
- realpath 和文件 inode 去重，同一个实际文件不会重复注入。

```markdown
# Memory
- [response-language] 默认使用中文交流，代码标识符保持英文。
- [review-before-commit] 修改完成后先展示 diff 和验证结果，不自动提交。
```

可省略 `# Memory`；允许空行和至少两个空格或一个 tab 的续行。每条使用 `- [id] 正文`，标识为 1–64 个 ASCII 字母、数字、连字符或下划线，以字母或数字开头，且文件内唯一。一条表达一个事实、偏好或约束。

每文件最多 20 条、正文共 2,000 个 Unicode code points。计数不含标识和列表语法，包含规范化的续行换行；忽略行尾空白和空行。emoji 按 code points 计数，不按 UTF-16 单元或视觉字形计数。格式错误、重复标识、无效 UTF-8、非普通文件或超限时，**整份文件不自动注入**，另一范围的合法文件仍可加载。设置仅常驻显示异常提示；点击「查看」可检查完整路径、容量及诊断，问号图标支持悬停或键盘聚焦查看说明。轮次上下文也带简短诊断；不会静默截断或修复磁盘内容。

原文件另有 64 KiB 读取上限，防止超长文件或大量空白拖慢刷新；超过时明确提示条数及正文尚未统计，拒绝注入且保留磁盘原文。

主 Agent 用现有 `read/write/edit` 维护文件：记住用户明确要求、明确纠正及已经确定的可复用约束；全局偏好写用户文件，项目规则写项目文件。修改前读最新内容，优先更新已有条目；满额先去重、合并或修正，无法合理腾出空间就不新增。用户要求忘记时删除对应条目，成功后简短说明。临时进度、一次性输出、未接受的建议、凭据和易从代码查得的信息不应保存。

程序硬性限制自动注入，不拦截外部编辑或任意 bash 写入。通过现有 `resourceLoader.reload()` 在用户轮次开始时读取，再由 `customInstructions` 纳入该轮固定上下文，不在工具循环中不断刷新。

## 长期记忆

存储位于当前活动用户存储 generation 的 `memories/` 下，与项目仓库、用户及项目短记忆文件分离。SQLite `StateStore` 持有设置、来源边界、成功水位、重试、用量和当前产物 generation 指针。

每个有效产物 generation 包含：

| 文件 | 用途 |
| --- | --- |
| `memory_summary.md` | 自动加载的简短摘要、重要偏好和检索导航 |
| `MEMORY.md` | 按工作区、项目和任务领域整理的详细经验、关键词和来源 |
| `rollout_summaries/*.md` | 每会话摘要、结果、适用范围、证据、会话 ID 和历史边界 |
| `raw_memories.md` | 可重新整合的逐会话原始记忆汇集 |

普通会话只自动加载摘要及使用说明。相关的复杂任务先从摘要取关键词，再用 bash 搜索详细 `MEMORY.md`，用 read 阅读最相关的 1–2 份会话摘要；只有需要精确证据时才沿摘要中的 `evidence_path` 读取原始会话导出快照。无需为简单请求搜索，也不扫描全部历史。设置中的「查看长期记忆」使用默认程序打开长期库 `MEMORY.md`，尚未生成时在页面内提示，不创建空文件。设置还提供来源会话导航，以及本轮 read 实际读取的摘要来源；聊天中的文件工具结果保留具体读取内容。通过 bash 直接读取不会自动计入 read 使用统计。

原始定位复用 ZPI `HistoryIndex` 的 generation/endSeq 和现有会话导出格式，不把 Codex JSONL 解析器搬入 ZPI。导出文件属于来源会话，删除该会话时由既有清理流程删除；不修改原始聊天。来源文件里记录工作区，项目经验不能自动推广到其他项目。

### 后台运行

符合条件的普通根会话首次建立执行 runtime 时异步检查；也可在设置点击「立即检查更新」。没有 cron。辅助对话和子智能体不触发检查，不作为独立历史提取来源；子智能体可继承父轮已经选取的记忆上下文，但不能自动维护共享短记忆或长期请求文件。

子任务继续执行时可继承父任务新轮次已经选取的上下文。应用重启后，不继续使用仅保存在子任务配置中的旧长期摘要；父任务重新选取后可再次继承，已有短记忆快照仍保留。清空会撤销父任务和子任务持有的长期摘要副本，在后续安全轮次生效。

默认只提取最近更新不超过 10 天、空闲至少 6 小时、当前未运行的普通历史根会话，每批最多 2 个。开启后可检查既有历史，快速对话、子智能体和辅助对话始终排除。设置中的高级选项可调整空闲门槛、历史窗口和批量上限。每次最多扫描 5,000 个近期候选；顺序执行提取和整合，单一 owner 防止重复批次。

1. 提取阶段读取实际用户输入、助手输出和执行证据。系统提示、准备后的用户消息、记忆文件读写结果及后台通知轮次被排除。明确区分人类要求、验证事实、助手提议、推断与未完成尝试；实际结构化问题答复可以作为用户证据，默认选项、超时或跳过不能。常见凭据会进行防御性脱敏，提示词禁止保存凭据；这不是对所有秘密格式的识别保证。
2. 允许双空输出表示无高价值内容，并保存成功处理边界；新版空输出会撤销该来源旧结果。半空、错误、取消和截断输出不视为成功。同版本最多失败 3 次，每次从实际失败时刻退避 1 小时；取消不消耗失败预算，来源版本前进时重置预算。
3. 整合阶段按实际使用次数和最近使用/来源更新时间选择最多 256 个来源，未使用窗口为 30 天。保留原始提取结果和来源摘要，以内容指纹判断输入变化；无变化且产物完整时跳过模型调用。删除、失效和无输出来源会从重建输入中撤除。仅被撤除来源支持的结论必须删除；混合来源保留仍受支持部分。
4. 输出先写独立临时 generation，经字段、容量和来源路径校验后发布 SQLite 指针。失败或取消不发布新产物。前台轮次及其子任务持有已选目录引用，避免后台发布时删除正在使用的旧目录；来源已撤销但尚未重新整合时，不向新轮次注入或导航旧库。输入不变但生成的原始汇集或来源摘要文件缺失时，从保存的提取结果恢复完整产物，无需再次调用模型；明确遗忘应记录请求或使用清空操作。

长期记忆中的明确 remember/forget/correct 请求通过独立的 `memory_notes.md` 保存：前台先读取最新文件，再用现有文件工具记录用户的明确请求、范围及会话来源，后台只读取这些请求并整合，不修改短记忆。遗忘/纠正请求会持续参与后续整合，不能从旧摘要恢复已被要求忘记的内容。请求在下一次符合条件的检查中应用，不等于前台已立即重新生成长期库。

「清空长期记忆」经确认对话框确认后取消批次并撤销发布权，删除长期库和请求文件，保留原始会话及短记忆；为当前历史保存清空边界，防止旧会话原样恢复。随后同一历史 generation 只提取该边界之后的新内容。若已清空来源的历史被重写为另一 generation，无法可靠区分旧内容时将该重写版本作为新的清空边界，不恢复其现存内容；其后新增的用户输入仍可积累记忆。删除或编辑历史成功后立即撤销相关来源，下一批再传播到新的有效产物。

### 模型及用量

- 跟随会话：冻结触发本批次会话的提供商配置、模型和思考强度，两个阶段共用；前台随后切换不改变已启动批次。设置页没有选中会话时，明确检查使用现有的最后一次模型选择。
- 手动指定：复用现有模型和思考级别选择组件。高级选项允许分别覆盖提取、整合模型。
- 缺失模型、不支持的思考级别或鉴权错误会显示原因，不自动切换模型或提供商。输入超过所选模型的保守上下文预算时明确失败，不静默丢掉证据。
- 后台用量单独记录，包含提供商报告用量的失败尝试；不计入前台任务统计。ZPI 当前桌面模型没有价格配置，费用显示未知。当前提供商没有统一额度查询接口，额度状态为未知，不能宣称充足；仍可运行自定义提供商，并始终限制单批工作量。

实际源码入口是 `codex-rs/memories/write/`、`codex-rs/state/src/runtime/memories.rs`、`codex-rs/ext/memories/`、`codex-rs/core/src/config/mod.rs` 和 `codex-rs/config/src/types.rs`。核对了阶段一/二实现、模板、workspace/storage 和对应测试，而非依据存在陈旧说明的 README。

该版本 memories 功能默认关闭。新 profile 启用后默认使用 `memories_v2/`，已有 v1 profile 使用 `memories/`；v2 不生成 raw memory 或详细 `MEMORY.md`，只生成摘要和 rollout summaries。ZPI 遵循本产品明确要求的 **v1 四文件分工和检索路径**，采用 v2 更严格的证据归属及偏好范围原则，不移植版本双写机制。

其余明确差异：

- 不生成、维护或注册 skills；不引入遥测、供应商默认模型或额度接口假设。
- 模型采用触发会话快照/手动选择/分阶段覆盖，替代 Codex 供应商 preferred model 及固定阶段思考级别。
- 使用两次受限的结构化 JSON 模型调用，由桌面写文件；整合模型没有 shell 或任意文件写权限。提取结果先保存到 SQLite，整合输入以对应的 raw memories 和 rollout summaries 内容传入模型，四类文件在通过整合校验后统一发布，避免暴露部分有效的产物。模板保留多任务、证据、范围、增量整理、来源删除和谨慎推断原则，但没有照搬 Codex 的整段技能提示词。
- 使用 ZPI 单应用 owner、SQLite 状态、内容指纹和原子 generation 发布，替代 Codex 文件锁、数据库任务租约和内部 Git 工作区；不增加通用任务框架。取消防回写、清空后的来源水位和旧有效产物保护比参考实现更严格。
- 保留 6 小时空闲、10 天窗口、每批 2 会话、最多 256 个整合来源、30 天未使用窗口、3 次失败及 1 小时退避。阶段一顺序执行；未额外照搬阶段二成功后的 6 小时冷却，改由输入指纹避免无变化调用。
- 证据导出最多最近 4,000 条记录，并沿用现有 128,000 字符历史导出限制；提取输入进一步有界为 120,000 code points，单字段输出上限 12,000；整合所选来源正文预算 300,000 code points，详细输出上限 100,000，摘要不超过 9,000 UTF-8 字节。截断带明确标记，不代表完整历史均被提取。
- 这是原生文件检索，没有向量数据库、定时执行框架、MCP 或浏览器自动化工具。core 四工具保持不变。桌面通过现有 `customInstructions`、资源刷新和会话事件接入，`SessionHost` 管理生命周期，`SettingsStore/StateStore` 管理持久化。

正常发布会回收无读者的上一代产物。崩溃时遗留的已发布旧目录可能保留到显式清空；原始证据导出随来源会话清理。应用没有跨项目数据访问隔离，也不能撤回已经发送给模型的上下文。清空和设置变化在后续安全用户边界影响注入，不能改写正在执行中的模型请求。
